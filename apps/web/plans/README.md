## Execution notes (deviations from the original plan text)

- **001**: the dot indicator's transform easing was corrected during review
  from `cubic-bezier(0.23, 1, 0.32, 1)` (ease-out) to
  `cubic-bezier(0.77, 0, 0.175, 1)` (ease-in-out) — resizing an existing
  on-screen element is "morphing," not "entering/exiting," per AUDIT.md §2.
- **007**: the plan's snippet assumed `current`/`reducedMotion` component
  state would be readable inside the `screens` array's `content` field —
  that field is a module-level constant with no closure over the component,
  so it can't reference state at all. Implemented instead as a CSS class
  (`.confirm-pulse-btn`) with the `@keyframes` and the
  `prefers-reduced-motion` override living in `app/globals.css`; the pulse
  fires automatically because the booking screen's subtree remounts each
  time `current` cycles back to index 2 (screens outside the active index
  aren't kept in the DOM). No JS state wiring needed.

## Recommended execution order

1. **001, 002, 004** first — independent, high-leverage, low-risk. Can run
   in parallel (different files, except 002 and 004 both touch
   `app/dashboard/stores/import/page.tsx` but different, non-overlapping
   elements — the button steps in 002 vs. the progress-bar block in 004).
2. **003** next — touches the same file as 001
   (`components/IPhoneMockup.tsx`) but a different block (the rotation
   `useEffect` and `slideStyle`, not the dot indicators). Run after 001 to
   avoid two agents editing the same file simultaneously; no functional
   dependency between them.
3. **007** depends on 003 — its reduced-motion gate assumes 003's
   `reducedMotion` state variable already exists in
   `components/IPhoneMockup.tsx`. Execute 003 before 007.
4. **005** any time — a config-only addition. If done before 001/004, those
   plans could reference the new `ease-out-strong` Tailwind token instead of
   inlining the cubic-bezier in `tailwind.config.js`'s sync comment; either
   order works since 001/004 use inline styles (not Tailwind classes) for
   their transitions regardless.
5. **006** independent of everything else — different file section
   (`app/page.tsx`'s grids) and a new standalone component.

## Dependencies
